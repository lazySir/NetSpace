## Shared data and API contract

Scan results keep their existing fields, with `networkId` (opaque string), `scanId` (integer), and enriched devices. Each enriched device has `deviceKey`, `profile`, `firstSeen`, `lastSeen`. `profile` is `{alias:'',notes:'',group:'',known:false,ignored:false}`. Original IP, MAC, hostname, status and evidence are retained.

Network identity uses CIDR, configured gateway, and resolved gateway MAC when available; otherwise use a conservative adapter-MAC fallback. MAC-based device keys survive IP changes within a network. Missing-MAC records can be promoted only when unambiguous. Networks and device records never use IP alone as permanent global identity.

Repository `network_store.py`, `NetworkStore(path=':memory:')` public methods:

```python
record_scan(result)  # returns enriched copy, atomic snapshot/profile/event transaction
list_networks()  # [{id,label,cidr,gateway,lastSeen,deviceCount}]
list_scans(network_id=None, limit=50)  # [{id,networkId,scannedAt,deviceCount,changeCount,durationMs}]
get_scan(scan_id)  # enriched snapshot or None
get_devices(network_id)  # all device records, profile + firstSeen/lastSeen + present
update_profile(network_id, device_key, changes)  # updated profile; unknown device raises KeyError
list_events(network_id=None, limit=50)  # event list
unread_count(network_id=None)  # notification events only
acknowledge_events(event_ids)  # positive integer ID list -> count updated
get_settings()  # {'notificationsEnabled': True}
set_settings(changes)  # validates/persists notificationsEnabled boolean
close()
```

Events contain `id,networkId,scanId,deviceKey,kind,ip,previousIp,name,occurredAt,read,notify`. Kinds: `new`, `returned`, `not_seen`, `ip_changed`. First scan establishes a quiet baseline. Later new devices emit one notification event; repeated sightings do not. Ignored devices create no notification; their pending notifications are marked read when ignored. Other changes remain a history trail. Never label absence as confirmed offline. Keep at most 500 snapshots and 2000 events per network; retain device profiles.

HTTP responses:

```text
GET /api/networks -> {networks:[...]}
GET /api/history?networkId=...&limit=50 -> {scans:[...]}
GET /api/history/123 -> {result:{...}}; absent ->404
GET /api/devices?networkId=... -> {devices:[...]}
POST /api/profile {networkId,deviceKey,alias,notes,group,known,ignored} -> {profile:{...}}
GET /api/events?networkId=...&limit=50 -> {events:[...],unreadCount:0,notificationsEnabled:true}
POST /api/events/read {eventIds:[1,2]} -> {updated:2}
GET /api/monitor -> {enabled:false,interfaceId:null,intervalSeconds:300,nextScanAt:null,error:null,notificationsEnabled:true}
POST /api/monitor {enabled,interfaceId,intervalSeconds,notificationsEnabled} -> same monitor shape
```

Monitor POST accepts partial settings, strict boolean values, and intervals 60/300/600 only. Enabling requires a currently available numeric interface ID, schedules immediate discovery, and maintains one active scan. Disabling stops future schedules; an already running discovery can complete. Shutdown stops scheduling and signals scan cancellation. Scan state also exposes `scanInterfaceId` and `monitor`; existing fields remain compatible. Manual scans remain available.

Profile constraints: alias <=80 characters, notes <=1000, group <=40; booleans must be bool. Database and handler errors return Chinese messages with no HTML injection. Unknown device/history ->404, invalid input ->400, concurrent scan ->409. Existing same-origin, loopback, body-size and static path protections apply to all endpoints.
