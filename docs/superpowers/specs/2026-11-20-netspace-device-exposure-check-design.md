# 单设备服务暴露检查设计

## 目标

让初次使用 NetSpace 的用户能对最近一次发现的单台设备执行明确授权、非破坏性的服务暴露检查。检查是真实 TCP 连接，但不执行利用、认证尝试、流量干扰或服务识别。

## 用户流程

用户完成一次真实发现、选择一台非本机设备、阅读提示、勾选已获授权并点击开始。服务端从所选网络的最新已保存快照中解析该设备 IP，并依次连接固定的七个常见服务端口（21、22、23、80、443、445、3389）；每次连接超时 350 ms。页面显示“可连接 / 拒绝连接 / 未响应 / 不可用”，任务可以取消，并解释观察结果及如何从路由器或设备本身关闭不需要的服务。演示与历史视图禁用检查入口。

## 边界与实现

- 服务只绑定 127.0.0.1；新接口复用 Host/Origin/Fetch-Metadata 校验，并对检查 POST 要求匹配的 Origin。
- 请求仅接受 networkId、deviceKey 和显式授权确认；不接受目标 IP、CIDR、接口、端口或 shell 参数。
- 服务端从最新本地保存快照按 deviceKey 找到当前地址，拒绝本机、非 IPv4 单播、超龄或不在接口网段的目标。
- 每次由用户点击启动一个后台任务；与网络发现、定时发现互斥；可取消，退出时取消；每目标固定七次、串行、短超时。TCP 建连本身会向目标发起连接并可能留日志。
- 结果只保存在内存，不落数据库、不记目标地址日志、不请求外部服务。
- 结果关联网络、设备与扫描记录；新扫描和 IP 变化不会沿用旧结果。有效期仅限制新任务，正在运行的任务保留查看与取消入口。
- 开放只表示 TCP 连接成功，不代表漏洞；不响应只表示本轮无法判断，不代表端口关闭。
- 测试连接器必须注入假对象；自动化检查不得调用系统网络发现或真实 socket 出站连接。

## 界面与无障碍

设备详情中展示清楚的中文说明、明确的授权勾选和“开始检查”按钮；进行时可取消；每个结果用文字呈现而不只依赖颜色。演示、历史、服务停止、缺少稳定设备标识与当前发现进行时均禁用入口。使用语义化对话框、键盘可达控件、状态播报和响应式版式。

## 验证与交付

先写后端与浏览器失败测试，再实现。测试 API 的来源保护、请求字段白名单、快照归属与新鲜度、本机/范围排除、超时取消、单次并发、扫描互斥、退出处理，以及模拟数据不会触发检查。运行完整 Python/浏览器回归、Windows 打包构建；不运行 Windows 原生网络发现或检查真实设备。README 记录用途、限制、截图和每轮变更，版本从 1.12.0 升到 1.13.0。
