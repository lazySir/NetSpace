# NetSpace 后续功能方向（2026-11-20）

本轮从 1.17.0 的实际代码出发，优先解决小白在已经保存的数据里找不到设备的问题。开发与验证仅使用虚构数据和本机回环服务。

WatchYourLAN 和 NetAlertX 的功能描述不意味着 NetSpace 具备它们的探测能力；本轮参考其产品方向，运行代码仍以仓库内的实现和测试为准。上游许可证不替代 NetSpace 自身的许可声明。

## 优先级与验收范围

| 优先级 | 方向 | 用户收益 | 具体范围与边界 |
| --- | --- | --- | --- |
| 1 / 本轮 1.18.0 | 已保存设备档案库 | 设备从最近一次发现中消失后，仍能找到别名、备注和上次地址 | 手动打开只读窗口，按保存的网络浏览；名称/分组模糊搜索，IP/MAC 片段匹配；筛选最近一次未见、待复核；分批显示卡片。复用现有只读 API，无新增设备连接。 |
| 2 | 单设备活动时间线 | 回答某台设备何时出现、地址何时变化 | 必须由服务端按 `networkId + deviceKey` 筛选后再限制条数，不能从网络最近 50 条记录里截取；展示历史裁剪与首条基准的限制。 |
| 3 | 拓扑图片导出 | 保存或向管理员说明某次发现的模拟关系 | 复用 Three.js，在本机合成视图和文字；图片须注明模拟坐标、推断连线、来源和时间，并正确处理无法绘制 3D 的情况。 |
| 4 | 备份检查与恢复 | 换电脑或误操作后找回本地档案 | 先做离线文件检查、格式/大小限制、完整性校验及恢复前预览，再设计原子恢复和回滚；独立迭代，不直接把任意 SQLite 文件覆盖工作数据库。 |
| 5 | 大档案分页与设备身份解释 | 长期使用和 MAC 随机化时仍保持清晰、流畅 | 后续添加服务端分页/检索与“档案不一定对应唯一物理设备”的解释；身份合并需要可回退的显式操作和独立测试。 |

## 本轮设计

- `network_store.py` 已保存 `deviceKey`、档案、首次/最近发现时间和 `present`；`/api/devices?networkId=…` 已提供这些数据。新窗口单独展示，不把旧档案放进当前 3D 场景或服务检查的目标上下文。
- “最近一次未见”仅表示未包含在所选网络最新一次保存的发现里；旧 `online`/`resolved` 状态不能用作现在仍在线的判断。
- 不按相同 IP 或 MAC 合并档案，保留网络内稳定的记录标识；MAC 随机化、多地址设备或 IP 重用可能产生多条档案。
- 手动打开或刷新时读取，搜索在浏览器本地完成；每次先显示 50 条，可继续显示。搜索索引在数据替换时建立，不在应用每次重绘时重建。现有服务端仍一次返回所选网络的全部档案，服务端分页留给后续迭代。
- 切换网络、关闭窗口、进入演示以及本地数据版本变化时，失效旧请求；清理后不能让迟到的读取把已删除记录带回界面。
- 未保存任何网络时显示下一步提示；读取失败提供重试；支持键盘关闭和 320 px 宽度。设备名称、分组和备注使用文本节点显示。

每一轮在测试、README、截图、Windows 构建完成后单独提交；尚未实现的方向不会作为现有功能宣传。
